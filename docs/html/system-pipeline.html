AI 眼镜记忆助手系统 Pipeline

当前真实主链路：先做文本清洗和原文证据保存，再构建最近上下文，Planner 给 baseline，Pre-Reply Decision 负责最终路由，随后按 gate 召回和仲裁证据，生成 answer directive，优先回复用户，最后后台沉淀长期记忆。

1系统入口与预处理—所有来源先变成可追溯文本

系统不是只有聊天框。Web 文本、浏览器语音转写、未来 App/ASR 文本、Markdown 文档和 continuous capture，进入长期记忆前都要先经过文本标准化、证据保存、隐私脱敏和 debug/audit。

2写入记忆细图—从清洗片段到 active memory

系统不是听到一句话就永久记住。短 turn 先抽候选；长输入先做语义清洗，只把值得抽取的片段交给候选抽取。候选再经过价值、隐私、敏感、重复和冲突治理，最后才可能进入长期记忆。

预处理

clean / segment

  • noise / correction
  • should_extract span
候选

candidate

  • profile / event
  • assistant_preference
门控

gate

  • 价值判断
  • 隐私 / 敏感判断
治理

dedupe / conflict

  • duplicate 合并证据
  • conflict / supersede
长期记忆

memory_store

  • active memory
  • status / strength

3路由、召回与回答—使用证据而不是让模型猜

查到记忆不等于一定使用。当前代码先用 planner baseline 和 pre_reply_decision 决定 gate，再执行召回、过滤和仲裁，最后由 answer directive 约束本地回复或主 LLM 回复。

本地基线

planner baseline

  • fast path
  • fallback / candidates
路由权威

pre_reply_decision

  • recall gate
  • recall_goal
召回仲裁

recall / guard

  • memory / timeline / document
  • drift_guard / arbitration
回答策略

local / directive

  • 确定性本地出口
  • LLM 回答约束
模型回答

LLM reply

  • <memory-context>
  • 受控上下文
