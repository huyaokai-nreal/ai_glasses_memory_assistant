一、这是什么

当前工程验证的是 AI 眼镜个人记忆助手的后端闭环：用户通过 Web 文本、浏览器语音、导入文本、Markdown 文档或 continuous capture 输入内容后，系统先保留原文证据，再把有长期价值的信息整理成结构化记忆，之后只在问题明确需要时召回。

已经具备的骨架

/api/chat、planner/router、timeline 原文、结构化记忆、文档归档、后台记忆 job、Debug/Audit、tests/evals 都已经连进主工程。

仍然只是原型

没有真实眼镜硬件 runtime、没有原生 App、没有音频上传和 ASR 管道、没有主动提醒推送，也没有生产级任务队列和账号权限系统。

产品上的正确理解

问题当前答案对应代码
用户原话是否保存？保存到 raw timeline/chunk，用于证据和“我之前怎么说”类问题。timeline_store.py
所有原话是否都变长期记忆？不是。长期记忆必须先变成候选，再过 should_write_memory_candidate() 门控。turn_planner.py、intent_policy.py
每轮都会读取所有记忆吗？不会。planner/router 明确打开 profile/event/timeline/document/observation 某个门时才召回 top-k。agent_bridge.py
文档细节靠摘要回答吗？不应该。摘要只帮助识别文档，细节问答要回到 documents.content 或命中片段。memory_store.py
后台 job 是否生产可靠？状态已最小持久化，重启后可解释；但没有 worker 重放、超时补偿和跨进程调度。timeline_store.memory_jobs

Pipeline 概念速查

概念解释
turn一轮交互边界：用户这句话、助手回复、debug、召回和写入结果都算在这一轮里。
timeline用户原话时间线，保存 raw turn 和 chunk，用来回答“我之前原话怎么说”。
chunk最小可搜索原文片段，也是结构化记忆能追溯到的证据单元。
planner / plan_turn()本地规划器，先判断该查什么、该不该记、能不能本地答。
fast path高频确定场景的本地快速回复，不进主 LLM。
routerplanner 拿不准时的结构化路由，只填决策表，不直接回答。
profile稳定用户画像、偏好和习惯。
event已发生或计划中的事件、任务、会议、承诺。
observation后台从多条带证据的 profile/event 中归纳出的回顾类记忆，用于“我最近在忙什么”这类问题。
memory job回复优先时的后台记忆写入任务，公开状态可从 SQLite 恢复，但不是可靠 worker 队列。
chat_audit.jsonl每轮诊断账本，出问题时先看这里。
设计作用
原话先写 timeline即使结构化摘要不完整，也能跨 session 找回用户原话。
planner 先判高频场景不必每次调 LLM，降低延迟和 token 消耗。
按需召回普通问题不默认读取所有个人记忆，减少误用上下文。
回复优先前端可传 defer_memory_writes=true，先回复，再后台写记忆。
写前门控敏感信息、低置信度、问题文本、临时上下文不静默落库。
全链路 audit出问题时看 chat_audit.jsonl，不用猜 planner 或 LLM 做了什么。

四、Memory Kernel：现在的记忆 contract

memory_kernel.py 是当前新增的轻量 contract。它没有引入新数据库或向量库，只统一“这条数据属于哪层、从哪里来、证据是什么、怎么删除、这次为什么召回”。

层存储/载体用途删除原则
raw_timelineraw_turns、captures、chunks保存用户原话和 capture chunk，服务全文回忆和 evidence。软删除 chunk；父 turn/capture 变成 partial/deleted。
structured_memorymemories、documents保存 profile、event、task、decision、assistant_preference 和文档记录。结构化记忆软删除；未共享 evidence chunk 同步软删除。
reflectionmemory_type=observation后台归纳长期模式，例如最近关注点、工程偏好、项目状态。纠错时 supersede，不静默覆盖源证据。
runtime_recalldebug.recall、<memory-context>当前 turn 注入的少量 top-k 背景上下文。只服务本轮，不作为新记忆持久化。
document_archivedocuments上传 Markdown 的完整原文和 metadata。软删除后不再参与召回。

Trace 字段看什么

字段出现位置解决的问题
source_tracememory/document/timeline/job/import 返回 payload这条记忆从哪里来，属于哪层，有哪些 evidence，隐私级别和删除策略是什么。
recall_tracedebug.memory.event_recall、debug.timeline.recall 等这次为什么召回，使用哪种策略，命中了几条，证据 ID 是什么。
memory_kernel.versiondebug.memory_kernel、import 结果帮助未来迁移或排查不同 contract 版本下的行为。
重要边界：Memory Kernel 是 contract，不是新存储引擎。当前仍然用 SQLite FTS/LIKE 和现有表，不新增 FAISS、图数据库或 embedding 依赖。

五、核心部件

Turn Planner

turn_planner.py 生成 TurnPlan，决定 fast path、召回、web/location、写候选和时间范围。

Structured Router

turn_router.py 只做路由，不直接回答。当前时间问题由本地系统时间生成确定性回复。

Memory Store

memory_store.py 管理 SQLite events.db，保存结构化长期记忆和 documents。

Timeline Store

timeline_store.py 保存 raw turn 和 chunk，服务原文搜索和 evidence 追溯。

Memory Write Gate

intent_policy.py 拒绝敏感内容、低置信度、问题文本和临时上下文。

Memory Kernel

memory_kernel.py 输出 source_trace / recall_trace，统一 evidence contract。

Audit / Debug

chat_audit.jsonl 与前端 Debug 面板解释每轮为什么这样答、为什么保存或拒绝。

结构化记忆类型

层级取值说明
顶层 kindprofile / event / assistant_preference决定召回和写入主类别。
二级 memory_typefact / event / task / preference / decision / project_state / observation用于周报、提醒和展示。

Fast Paths

场景路径效果
问候reply_mode=greeting本地回复，不读写记忆，不创建主 agent session。
身份查询reply_mode=identity_query读取 profile / assistant_preference，本地回答。
画像陈述reply_mode=profile_statement生成 profile 候选，过门控后同步保存。
事件记录reply_mode=event_record_ack先快速回复“我先记下”，后台处理 event 保存。
原文回忆reply_mode=local_timeline_recall明确问“原话/之前怎么说”时查 timeline chunk。
回顾归纳event_recall_strategy=observation_review明确问最近关注点、工程偏好、项目状态时读 observation。

六、数据存在哪里

两个 SQLite 库分工明确：结构化长期记忆放在 events.db，原文时间线和后台公开状态放在 timeline.db。默认目录来自 get_hermes_home() / "ai_glasses_memory_assistant"。

存储表/对象保存什么不要误解为
events.dbmemoriesprofile、event、assistant_preference、task、decision、project_state、observation。不是聊天全文库。
events.dbdocuments上传 Markdown 的 filename、title、summary、content、content_hash、status。不是把文档每行都变 event。
timeline.dbraw_turns每轮用户原话、助手回复、旧 session 线索。不是每轮默认注入上下文。
timeline.dbchunks / chunks_fts可搜索原文片段，FTS5 可用时走 FTS，不可用走 LIKE fallback。不是结构化记忆替代品。
timeline.dbcapturescontinuous capture 元数据和重启后 stop/import 恢复。不是硬件 ASR runtime。
timeline.dbmemory_jobs后台记忆 job 的公开 payload，便于重启后查询状态。不是可靠 worker 队列。
文件chat_audit.jsonl聊天、导入、后台写入、提醒检查等可复盘记录。不是用户可见的正式数据导出。

七、API 和输入来源

入口当前实现关键边界
POST /api/chat主聊天入口，转到 GlassesChatService.chat()。必须先写 timeline，再 planner/router，再召回和回复。
GET/POST/DELETE /api/memories查看、手动新增、删除结构化记忆。删除结构化记忆时，未共享 evidence chunk 会同步软删除。
POST /api/memory/import文本/JSON 导入；source="markdown_upload" 时归档 document。导入不能绕过 should_write_memory_candidate()。
/api/capture/start|append|stop连续输入 API；append 写 chunk，stop 汇总后走 import。验证长输入管道，不是硬件常驻收音。
GET /api/memory/jobs按 user_id + job_id 查询后台写入状态。可恢复公开状态，不承诺 worker replay。
GET /api/timeline/search调试和原文搜索。不是完整 timeline 管理 UI。
GET/PATCH/DELETE /api/documents/{id}读取、编辑、删除文档原文和 metadata。删除后不再参与召回。
GET /api/weekly-report按 event/task/decision/project_state 生成周报草稿。启发式草稿，不是完整项目知识图谱。
GET /api/reminders/check手动检查未来 24 小时 task 候选。不是主动提醒推送 runtime。
POST /api/tts生成语音音频，供前端播放。只是 demo 播报能力。
GET /api/debug/audit读取最近 audit 记录。排障入口，不是最终用户报告。

多输入来源统一原则

聊天 / 文本导入 / JSON 导入 / Markdown 文档 / continuous_capture / 未来 ASR 转写文本
-> 标准化输入
-> 原文或文档归档
-> 候选抽取
-> should_write_memory_candidate()
-> 去重/合并 evidence
-> 保存或拒绝
-> debug/audit
