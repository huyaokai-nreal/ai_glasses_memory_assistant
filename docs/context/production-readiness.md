# 生产级完整记忆系统定义

本文用于回答“当前底层记忆机制距离生产级 AI 眼镜完整记忆系统还有多远”。它不替代 `PLANS.md` 的开发顺序，也不把未来能力写成当前已完成能力。

## 一句话定义

生产级 AI 眼镜完整记忆系统不是“能存几条记忆、能搜出来”，而是：

```text
多来源可靠输入
-> 隐私和权限门控
-> 可追溯长期记忆
-> 稳定召回和回答组织
-> 用户可控管理
-> 主动服务
-> 生产级可靠性、账号、安全和运维
```

当前项目已经完成的是其中的“纯文字输入下的底层记忆内核第一版闭环”。它能验证写入、召回、纠错、证据、删除、debug/audit 和 eval，但还不是完整产品系统。

## 分层判断

| 层级 | 生产级要求 | 当前状态 | 距离 |
| --- | --- | --- | --- |
| 输入 runtime | 真实眼镜语音、手机文本、文档、音频、位置、日历等统一接入；理想眼镜侧包括可见持续收音待机和唤醒后 query。 | 当前是 Web 文字、浏览器语音、文本/JSON 导入、Markdown 文档和 `continuous_capture`；持续收音待机规划见 `ambient-audio-wakeword-plan.md`。 | 输入形态仍是 demo 级，未实现 always-on audio runtime。 |
| ASR 与预处理 | 音频上传、稳定 ASR、断句、噪声过滤、说话人、时间地点绑定、短期原话时间线和轻量情绪元数据。 | 没有原始音频上传和生产级 ASR；浏览器语音只是交互替身；情绪判断尚未进入主链路。 | 缺产品级音频链路和唤醒式现场问答。 |
| 写入内核 | 候选抽取、隐私门控、去重、冲突更新、纠错、状态机。 | 纯文字链路已完成第一版，`memory_mechanism` active eval 覆盖主要机制。 | 内核雏形较完整，仍需更长上下文和项目结构化扩展。 |
| 原文证据 | 原话、capture chunk、文档原文可追溯、可删除。 | 已有 raw timeline、document、evidence 引用、软删除和 `purge=true` 第一版。 | 还缺完整审计后台、批量纠正和 document chunk 引用。 |
| 召回和回答 | 按问题选择 profile/event/document/raw/observation，不混用证据。 | 已有多来源召回仲裁、drift guard、confidence policy。 | 需要更多真实长上下文和跨来源组合验证。 |
| 用户控制 | 查看、纠正、删除、彻底删除、导出、权限和来源管理。 | 记忆面板已有查看、搜索、文档编辑/删除、timeline evidence 查看和批量删除第一版。 | 还不是完整 App 管理后台。 |
| 主动服务 | 授权提醒、触发窗口、勿扰/抑制、周报、复盘和主动建议。 | 只有手动 `check_reminders()` 和启发式周报草稿。 | 主动 runtime 未实现。 |
| 生产可靠性 | 多设备同步、离线缓存、重试、幂等、账号权限、加密、监控、恢复。 | SQLite 本地 demo，job/capture 只有最小持久化公开状态。 | 仍不是生产服务。 |

## 具体例子

### 例子一：真实眼镜全天输入

生产级系统应该能接收一天中的语音片段、位置变化和手机补充输入，并判断哪些是闲聊、哪些是待办、哪些是会议决策、哪些不该保存。若采用持续收音待机形态，还需要明确“短期原话缓存”和“结构化长期记忆”的边界：唤醒前现场语境可用于当前回答，但周围人的话不能默认进入用户长期记忆。

当前系统只验证“文本已经进来后怎么进入记忆管道”。例如用户粘贴会议纪要，系统可以低打扰确认并后台抽取任务、决策和风险；但真实眼镜常驻收音、ASR、断句、噪声过滤、唤醒词、轻量情绪元数据和授权边界还没有。专项规划见 `ambient-audio-wakeword-plan.md`。

### 例子二：主动提醒

生产级系统应该在用户授权后，根据任务时间、当前位置、勿扰状态和触发窗口主动提醒，并记录为什么触发或跳过。

当前系统能把 `memory_type=task` 写成 open/completed/cancelled，也能手动调用 `/api/reminders/check` 检查未来 24 小时任务；但没有后台调度、推送通道、静音/抑制策略和主动触发 audit。

### 例子三：用户可控管理

生产级系统应该让用户知道“这条记忆来自哪句话、哪段录音或哪份文档”，并支持纠正、删除、彻底清除、导出和来源权限控制。

当前系统已有记忆/文档面板、timeline 原文搜索、evidence 抽屉、批量软删除和彻底删除第一版；但还不能作为完整审计后台，也不支持复杂纠正 workflow 或音频证据管理。

### 例子四：可靠后台

生产级系统不能因为进程重启、网络失败或设备离线而丢失关键记忆。后台任务需要重试、恢复、幂等、任务所有权和跨进程调度。

当前 `memory_jobs` 和 `captures/chunks` 能把公开状态写入 SQLite，重启后可以查询或继续 stop/import；但这只是 demo 级持久化，不承诺 worker 重放、抢占、超时补偿或多设备同步。

## 当前阶段判断

- **底层文字记忆内核**：第一版闭环已经基本完成，可以继续作为后续音频、App、眼镜输入的统一后端管道。
- **完整 AI 眼镜产品系统**：仍处在早期验证阶段，主要缺输入 runtime、持续收音/唤醒式现场问答、主动服务、App 管理体验和生产可靠性。
- **生产级上线系统**：还需要账号权限、安全加密、同步、监控、任务队列、真实设备/手机端和长期真人测试。

下一步如果继续做“生产级”，优先不要重写记忆库；应把现有文字记忆管道接到产品能力上：音频转写、App 输入、主动提醒授权、用户可控管理和可靠后台。
