# 2026-06-08 Codex/agent 持续聊天真实语境压测

## 用户现在能感受到什么变化

这次不是再看固定 eval，也不是只读代码推测，而是直接让 Codex 扮演真实用户，用当前 demo 和 `DeepSeek-chat` 连续对话，观察系统在自然聊天、临时偏好、自然纠错和后续追问里的真实表现。

这样后续优化时，我们能明确知道：

- 哪些句型已经守住了。
- 哪些句型还会误写长期记忆。
- 哪些纠错会把旧记忆修好，哪些纠错会把库写脏。
- 长轮次真实聊天里，用户会先感知到哪些慢回复问题。

## 本次压测方式

- 模型：`DeepSeek-chat`
- 路由模式：`llm_first`
- 运行方式：直接调用当前 `GlassesChatService.chat()`
- 隔离方式：每组对话使用独立临时 `HERMES_HOME` 和新 `user_id`，避免历史记忆污染
- 证据来源：
  - 临时 `events.db`
  - 临时 `chat_audit.jsonl`
  - 每轮 debug 中的 `memory_processing`、`source_summary`、`timing`、`correction_target_resolution`

## Persona 1：AI 眼镜 demo / audit / 临时饮料偏好

### 对话片段

1. `你好，我最近在推进 AI 眼镜 demo，这两天要先把 debug 面板再顺一遍。`
2. `对了，明天下午我和 Alex 过一下 audit 面板的慢回复问题，先别忘。`
3. `不过这个不算长期偏好，只是这两天我可能都喝东方树叶，先别记成我一直喜欢。`
4. `刚才会议时间我说错了，不是明天下午，是后天上午十点。`
5. `那我这两天主要在忙什么？`
6. `我喜欢喝什么？`
7. `后天我要做什么？`

### 已确认问题

#### 1. 普通近况被过度写成 task

首轮输入更像自然开场和近况交代，但系统直接写入：

- `正在推进 AI 眼镜 demo，近期需要完成 debug 面板的梳理`
- `memory_type=task`
- `tags` 里还错误带了 `task_status:completed`

用户体感：

- 我只是随口说近况，系统却把它记成明确待办。
- 甚至还把状态理解成“已完成”，和真实语义相反。

### 2. 明说“先别记成长期偏好”仍被写入长期记忆

第三轮后，库里出现：

- `可能都喝东方树叶`
- `memory_type=preference`
- `status=active`

同时 observation 也把这条临时饮料信息吸收进去了。

用户体感：

- 我明明在降级这个事实，只想保留成临时上下文。
- 系统还是把它沉淀成长期画像，后面容易误答“你喜欢喝东方树叶”。

### 3. 自然纠错没有 supersede 旧记忆，反而写出脏记忆

第四轮纠错后，没有把原来的

- `明天下午和Alex过一下audit面板的慢回复问题`

替换掉，而是新增了两条 active 记忆：

- `会议时间我说错了，不是明天下午，是`
- `后天上午十点`

`debug.memory_processing.correction_target_resolution` 显示走到了：

- `resolution_backend=llm`
- `fallback_reason=low_confidence`
- `treatment=fallback_no_supersede`

用户体感：

- 我纠正一次，系统里同时留下旧版、残句版和碎片版。
- 后续问“后天我要做什么”时，系统会继续吃这些脏数据。

### 4. 脏记忆会继续污染后续追问

后续问 `后天我要做什么？` 时，audit 显示主要依据已经变成：

- `primary_source=structured_memory`

而这批结构化记忆里，正包含上面新增的残缺纠错记忆。

用户体感：

- 不是只错一轮，而是后面越问越乱。
- 一次纠错失败会扩散到后续所有相关追问。

### 5. 连续聊天首轮就偏慢

首轮 `timing.total_seconds=17.39`，主要耗时段包括：

- `structured_router=5.95s`
- `memory_extraction=2.17s`
- `query_temporal_resolution=2.17s`
- `answer_directive=2.46s`

用户体感：

- 一句普通近况都要等很久。
- 连续聊天里这种延迟会非常明显。

### Persona 1 当前已确认的实际落库

- `后天上午十点`

## Persona 2：周报链路 / 文档追问 / 临时咖啡偏好

### 对话片段

1. `我刚搬到新的工位，这周主要想把周报生成链路再过一遍，不过先只是看看，不一定立刻做。`
2. `顺便记一下，周三下午两点要和 Mia 过一下文档追问为什么会串上下文。`
3. `但咖啡这事先别记，我这周只是暂时改喝美式，不代表我以后都喜欢。`
4. `不对，时间我说错了，不是周三下午两点，是周四上午十一点。`
5. `那这周我主要在忙什么？`
6. `我喜欢喝什么咖啡？`
7. `周四我要做什么？`

本轮脚本在运行到后半段前已明显变慢，但前 4 轮证据已经足够说明一些边界。

### 已确认现象

#### 1. “临时偏好不要记”在这组表达里守住了

第三轮没有写入新的咖啡偏好，`debug.memory_processing` 显示：

- `status=not_needed`
- `decision_reason=source_transient_context_only`
- `skip_policy.role=ephemeral_context`

说明当前系统对“这周只是暂时改喝美式，不代表以后都喜欢”这类句型，已经能识别成临时上下文，而不是长期画像。

这是一条重要正例，后面不要把这类已守住的边界又改坏。

#### 2. 但第一轮“先只是看看，不一定立刻做”仍被写成 open task

首轮写入了两条：

- `用户搬到新工位`
- `本周计划回顾周报生成链路，暂不立即执行`

第二条虽然包含“暂不立即执行”，但仍以 `task_status:open` 落库。

用户体感：

- 我只是说这周可能看一下，并没有真正承诺任务。
- 系统还是偏向把“软计划/试探性安排”写成正式待办。

#### 3. 第二组首轮更慢

首轮 `timing.total_seconds=30.86`，主要耗时段包括：

- `structured_router=9.59s`
- `memory_extraction=3.95s`
- `answer_directive=3.90s`
- `memory_write=5.55s`

这说明慢回复不是 Persona 1 的偶发现象，而是在真实连续聊天里可复现的问题。

## 这次压测得到的结论

### 已经守住的边界

- `临时偏好 + 明确说先别记/暂时/不代表以后` 在部分表达里已经能停在 transient context，不落长期记忆。

### 仍然不稳的边界

- 普通近况和项目背景容易被过度任务化。
- “临时偏好不要长期记”仍存在表达敏感性，不同说法会分化。
- 自然纠错在任务/日程类场景里，仍可能无法 supersede 旧记忆，反而长出碎片记忆。
- 一旦纠错失败，后续 recall 会继续吃脏记忆。
- 多轮真实聊天下延迟偏高，而且不是单轮偶发。

## 后续最值得优先补的 target / 修复方向

### P0：纠错 target

- 自然纠错后旧 task 应 supersede，而不是并存。
- 禁止把纠错句的前半残句写成 active memory。
- 禁止把纯时间片段单独写成 task。

建议新 target 方向：

- `real_context_natural_correction_task_supersede_target`
- `real_context_correction_does_not_create_fragment_memories_target`

### P0：临时偏好降级 target

- 补齐“这两天可能都喝 X，先别记成一直喜欢”这类目前仍会漏写的表达。
- 保持现有 `glasses_temporary_preference_not_profile` 正例继续通过。

建议新 target 方向：

- `real_context_transient_preference_variant_not_profile_target`

### P1：普通近况 vs 正式任务边界

- “最近在推进 / 这周想过一遍 / 先看看 / 不一定立刻做” 不应默认等于 open task。
- 需要区分：
  - 背景近况
  - 软计划
  - 已确认待办

建议新 target 方向：

- `real_context_soft_plan_not_open_task_target`
- `real_context_project_background_not_over_taskified_target`

### P1：慢回复分段诊断

- 把真实多轮聊天里的慢段拆到 `structured_router`、`memory_extraction`、`answer_directive`、`memory_write`
- 先做诊断，不要立刻为了快而破坏当前边界

## 2026-06-08 加压续测：更口语化角色

这轮继续往更像真实用户的方向压，不再只用“项目、周报、链路”这种偏工程表达，而是故意加入：

- 碎碎念
- 改口
- “先别当真”
- “你先帮我记着”
- 生活吐槽夹真正任务

截至目前，已经连续补测了多组更口语化 persona。下面先记录当前最值得后续修复时反复对照的共性现象，再补一组最新拿到完整证据的代表性案例。

## 当前多组口语化 persona 的共性问题地图

- 口语命令前缀会污染记忆正文，例如：
  - `你先帮我记一下`
  - `你给我记一下`
  - `真要记的是`
  - `你先替我记一下`
- 临时偏好的边界不稳定：
  - 有些表达已经能命中 `source_transient_context_only`
  - 有些表达只是偶然被低置信度拒绝，并不是真正守住了临时语义
  - 还有些表达仍会直接误写成长期开启的 `preference`
- 临时情绪、心理状态、自我评价，容易被上升成长期 `observation`
- 家人/亲密关系里的碎念，有时会被升格成过度确定的长期 `fact`
- 模糊社交状态、嘴上客套、含糊承诺，会被系统过度结构化
- 自然纠错普遍还不干净：
  - 旧任务没有被 supersede
  - 或者只剩时间，不剩具体事项
  - 会长出 `周六晚上`、`应该是周五下午`、`截止时间是周日晚上` 这类碎片记忆
- `observation` 反射层会继续放大脏输入，有时甚至生成残句或过度概括
- 慢回复问题在真实多轮聊天里可复现，尤其首轮，`structured_router` 经常是主要慢段

## Persona 10：表面无所谓、其实很在意评价型

### 对话片段

1. `我嘴上是说随便他们怎么评价我啦，但真有人说我不行，我还是会偷偷想半天。`
2. `不过你先帮我记一下，周五傍晚我要把那版东西再看一遍，免得别人一说我又上头。`
3. `还有啊，我最近也不是突然变得特别自律，就是这两天有点怕再被说。`
4. `欸不对，时间我刚说早了，不是周五傍晚，改成周五晚上。`
5. `那我最近在意的点是啥？`
6. `周五我要干嘛？`

### 已确认问题

#### 1. 当下评价焦虑被长期化成稳定画像

第一轮本来更像一种当下情绪和自我剖白，但最终落成 active `observation`：

- `嘴上说不在意别人评价，但被否定时会在意很久`
- `memory_type=observation`
- `status=active`
- `confidence=0.9`

用户体感：

- 我是在描述最近这阵子的心态，不是在确认一个想长期被保存的人格标签。
- 系统会把“当下会多想”直接沉淀成长期画像，后面追问时就容易被答成稳定性格结论。

#### 2. 任务正文仍被口语前缀污染

第二轮真正要记的待办落成了：

- `不过你先帮我记一下，傍晚我要把那版东西再看一遍，免得别人一说我又上头`
- `memory_type=event`
- `status=active`

用户体感：

- 真正该记的是“周五傍晚再看一遍那版东西”。
- 但系统把 `不过你先帮我记一下` 这种口语指令也一起写进正文，后续召回会显得很脏、很不像用户原本想保存的事项。

#### 3. 自然纠错后仍只留下抽象时间变化

第四轮纠错后，库里新增的是：

- `活动时间改为周五晚上`
- `memory_type=event`
- `status=active`

也就是说，纠错并没有把“周五晚上再看一遍那版东西”这件完整事项修干净，而是又长出一条偏抽象的时间改动记忆。

用户体感：

- 我明明是在纠正同一件事的时间。
- 结果系统没有把完整任务更新好，而是额外留下“改成周五晚上”这种半抽象描述，后面一问就容易只剩时间，不剩事情本身。

#### 4. 首轮依然能明显感知到慢

这一组首轮：

- `timing.total_seconds=15.684138`
- `structured_router=6.157518`

用户体感：

- 这种只是口语化自述加一个轻任务的开场，理论上应该很顺。
- 但实际仍然会感觉到第一轮明显卡顿，说明慢回复不是只在工程类表述里出现。

### Persona 10 当前已确认的实际落库

- `嘴上说不在意别人评价，但被否定时会在意很久`
- `不过你先帮我记一下，傍晚我要把那版东西再看一遍，免得别人一说我又上头`
- `活动时间改为周五晚上`

## 这轮加压续测后，最值得优先修的仍是这几类

- 临时心理状态 / 自我评价不要轻易长期 observation 化
- 任务正文需要去掉 `你先帮我记一下` 这类口语指令前缀
- 自然纠错应更新完整事项，而不是只留下抽象时间碎片
- 慢回复排查继续优先看 `structured_router` 这类首轮慢段

## Persona 11：嘴上说没事、其实会记仇型

### 对话片段

1. `我嘴上一般都说算了没事，但别人要是真当着面让我下不来台，我其实会记挺久的。`
2. `你先替我记一下，周六下午我要把给小郑的那条消息补发了，别拖到又尴尬。`
3. `吃辣这个先别记成我真爱吃啊，我就是这两天心里有点堵，想吃点重口的。`
4. `欸我刚说错了，不是周六下午，是周六晚上。`
5. `那你说，我最近卡在哪种情绪里？`
6. `我最近是不是爱吃辣？`
7. `周六晚上我要干嘛来着？`

### 已确认问题

#### 1. 人际受挫后的临时情绪，直接被长期写成 `preference`

第一轮系统保存的是：

- `用户嘴上常说算了没事，但被人当面难堪时会记仇很久`
- `kind=profile`
- `memory_type=preference`
- `status=active`
- `confidence=0.95`

这里不只是“被长期化”这么简单，而是类型也偏了。

用户体感：

- 我是在描述一种当下很口语化的情绪反应，不是在声明一个想长期保存的“偏好”。
- 系统把“会记挺久/会记仇”这种人际挫败反应，沉淀成了高确定性的长期 `profile.preference`，后面很容易被答成稳定人格设定。

#### 2. 任务正文仍然把口语指令前缀一起存进去

第二轮后台实际落库成了：

- `你先替我记一下，我要把给小郑的那条消息补发了，别拖到又尴尬`

用户体感：

- 真正该记的是“周六下午补发给小郑的消息”。
- 但系统还是把 `你先替我记一下` 这种口语化命令前缀一并写进正文，说明这类噪声污染并不是某一个说法的偶发问题。

#### 3. 临时重口味这次守住了，但回复措辞已经开始替用户总结

第三轮没有误写“爱吃辣”长期偏好，`events.db` 里也没有新增辣味相关 active `preference`，这是正例。

但系统回复是：

- `记住了，不吃辣是你临时解压，不是日常口味。`

用户体感风险：

- 存储层这次守住了，可回复层已经替用户下了“临时解压”这种总结。
- 后续如果回答层越来越主动解释，可能会先在回复上产生“被理解过度”的体感，即便后台暂时没写脏。

#### 4. 自然纠错仍没有把完整事项修干净，只长出裸时间 task

第四轮纠错后，最终 active 记忆里同时存在：

- 旧任务：`你先替我记一下，我要把给小郑的那条消息补发了，别拖到又尴尬`
- 新碎片：`周六晚上`

`events.db` 里这条新碎片已经变成：

- `kind=event`
- `memory_type=task`
- `content=周六晚上`
- `status=active`

用户体感：

- 我明明是在纠正同一件事的时间。
- 结果系统没有把“补发给小郑消息”这件完整事项更新时间，而是又长出一个只有时间、没有事情本体的 task。

#### 5. 纠错后的 observation 反射会继续放大这种脏输入

后续库里还出现了 active `observation`：

- `用户虽表面说算了，但曾在让小郑的未发消息提醒自己别拖到尴尬，显示其对人际尴尬记忆深刻且在意`

用户体感：

- 原本只是几句带情绪的自然说话，系统却进一步抽象成了“对人际尴尬记忆深刻且在意”的长期总结。
- 而且这条总结还吸收了前面已经带噪声、带碎片的问题记忆，说明 `observation` 反射层会继续放大污染。

#### 6. 后续追问会吃这批脏记忆，但“爱吃辣”这条追问目前主要靠低置信拒绝守住

第六轮问：

- `我最近是不是爱吃辣？`

这一轮没有新增辣味偏好，`debug.memory_processing` 显示走的是：

- `status=rejected`
- `decision_reason=candidate_confidence_below_threshold`

用户体感风险：

- 这轮没写错是好事，但它更像“低置信度挡住了”，而不是稳定命中“临时上下文不要长期化”的策略。
- 也就是说，换个相近说法，仍可能误写。

#### 7. 首轮依旧很慢，而且不是复杂工程语境才慢

第一轮只是很生活化、很口语化的一句：

- `我嘴上一般都说算了没事，但别人要是真当着面让我下不来台，我其实会记挺久的。`

但 audit 里显示：

- `timing.total_seconds=24.061676`
- `structured_router=9.712241`
- `memory_extraction=3.392922`
- `answer_directive=4.283777`

用户体感：

- 连这种更像真实碎碎念的开场都要等二十多秒，说明慢回复不是只在工程型问法里出现。

### Persona 11 当前已确认的实际落库

- `profile|preference|用户嘴上常说算了没事，但被人当面难堪时会记仇很久|active|0.95`
- `event|event|你先替我记一下，我要把给小郑的那条消息补发了，别拖到又尴尬|active|0.95`
- `event|task|周六晚上|active|0.92`
- `event|observation|用户虽表面说算了，但曾在让小郑的未发消息提醒自己别拖到尴尬，显示其对人际尴尬记忆深刻且在意|active|0.9`

## 这组新增后，又进一步确认了几条优先修复方向

- 人际受挫、委屈、记仇、在意难堪这类临时心理反应，不该直接长期化，更不该误标成 `preference`
- 口语命令前缀污染不是单个短语问题，`你先替我记一下` 这一类仍会稳定入库
- 自然纠错在任务场景里仍会生成裸时间 task，完整事项更新没有真正修干净
- `observation` 反射层会继续吃这些带噪声的记忆，再次放大长期画像污染

## 阶段性收敛：当前最稳定复现的问题簇

压到现在，问题已经不再是“某一句偶尔答歪”，而是开始收敛成几类稳定复现的结构性问题。后面无论补 target、改 gate 还是调 observation reflect，都可以优先对着这几簇下手。

### 1. 口语命令前缀污染任务正文

典型触发句：

- `你先帮我记一下`
- `你给我记一下`
- `你先替我记一下`
- `你先帮我记着`

当前稳定现象：

- 这些口语命令前缀会被原样写进 `event/task` 正文，而不是只保留真正要记的事项。

用户体感：

- 后续 recall 很脏，像在复述没清洗的原话，不像整理后的记忆。

### 2. 自然纠错只留下时间碎片，更新不干净

典型触发句：

- `不是明天下午，是后天上午十点`
- `不是周五傍晚，是周五晚上`
- `不是周六下午，是周六晚上`

当前稳定现象：

- 旧任务经常没有被干净 supersede
- 新记忆只留下：
  - `后天上午十点`
  - `活动时间改为周五晚上`
  - `周六晚上`
  - `截止时间是周日晚上`

用户体感：

- 用户明明在纠正同一件事，系统却把“时间变化”单独存起来，真正要做的事情反而丢了。

### 3. 临时偏好 / 临时情绪 / 临时心理状态被长期化

典型触发句：

- `这两天可能都喝东方树叶，先别记成我一直喜欢`
- `我就是这两天烦，想喝点冰的`
- `我最近有点怕再被说`
- `别人真让我下不来台，我会记挺久`

当前稳定现象：

- 有时直接写成 active `preference`
- 有时写成 active `observation`
- 更糟的是，偶尔连类型都会偏，比如把“记仇/难堪”写成 `profile.preference`

用户体感：

- 很短期、很情境化的状态，被系统沉淀成“你就是这样的人”。

### 4. 模糊社交 / 家庭碎念 / 职场客套被过度结构化

典型触发句：

- `嘴上说改天，其实心里没定`
- `嘴上嫌她烦，其实知道她是为我好`
- `这事我们回头再对一下，其实很多时候我只是先客气接住`

当前稳定现象：

- 会被写成高置信度长期 `observation` 或 `fact`
- 甚至系统回复里也会主动替用户下定义，例如：
  - `以后你说“回头对一下”，我就当“先放一放”`

用户体感：

- 很多本来只是社交润滑、家庭碎念、口头客气的话，被系统理解成了稳定人格规则。

### 5. observation 反射层会继续放大前面的脏输入

当前稳定现象：

- 前面已经带口语噪声、带纠错碎片、带临时情绪的记忆，会被 observation 再抽象一层。
- 抽象后常出现：
  - 更稳定的人格化总结
  - 把多个临时状态揉成一条 observation
  - 残句或业务语义缺失

用户体感：

- 问题不是只脏一条，而是会越滚越大，后续总结类问题会越来越像“被系统过度解读”。

### 6. “没写错”不等于真的守住了，很多时候只是低置信拒绝

当前稳定现象：

- 有些临时偏好 / 试探性追问没有误写，这本身是好事。
- 但 debug 显示不少场景实际走的是：
  - `candidate_confidence_below_threshold`
- 而不是稳定命中：
  - `source_transient_context_only`

用户体感风险：

- 这说明边界还不稳，换个说法就可能重新掉坑。

### 7. 首轮慢回复是可复现问题，而且不挑语境

当前稳定现象：

- 工程语境慢
- 生活语境慢
- 情绪碎碎念也慢
- 目前反复出现的主要慢段还是：
  - `structured_router`
  - `memory_extraction`
  - `answer_directive`

用户体感：

- 很多看上去只是一句普通口语开场，实际都要等十几秒甚至二十多秒。

## Persona 12：职场客套 / 委婉拒绝型

### 对话片段

1. `我嘴上一般都会说这事我们回头再对一下，但其实很多时候我只是先客气接住，不代表我真想接。`
2. `你先帮我记一下，周五下班前我要给陈姐回个消息，至少把态度说明白，别一直晾着。`
3. `甜咖啡这个先别记成我真喜欢，我就是这两天开会开麻了，想喝点甜的缓一下。`
4. `欸不对，不是周五下班前，是周五晚上。`
5. `那你说，我最近到底在敷衍哪种事？`
6. `我最近是不是就爱喝甜咖啡？`
7. `周五晚上我要干嘛来着？`

### 已确认问题

#### 1. 职场客套话会被直接长期 observation 化

第一轮直接落库成了：

- `说'这事我们回头再对一下'时，很多时候只是客气接住，不代表真想接`
- `kind=profile`
- `memory_type=observation`
- `status=active`
- `confidence=0.9`

用户体感：

- 这更像职场客气话和当下沟通策略，不一定想变成一个长期人格规则。
- 系统却已经把它沉淀成稳定画像了。

#### 2. 系统回复还会进一步替用户定义这条“行为规则”

第一轮回复直接说：

- `以后你说"回头对一下"，我就当"先放一放"。`

用户体感风险：

- 这不只是后台写了长期 observation，前台回复也开始替用户固化一条行为解释。
- 会让用户感到自己被系统“定性”了。

#### 3. 任务正文继续带口语命令前缀

第二轮 active 记忆里仍然是：

- `你先帮我记一下，下班前我要给陈姐回个消息，至少把态度说明白，别一直晾着`

这说明职场语境下，口语前缀污染正文的问题依旧存在。

#### 4. 临时甜咖啡没有直接变成 preference，但被 observation 吸成了长期总结

第三轮后，库里出现的不是甜咖啡 `preference`，而是：

- `用户最近开会频繁感到疲惫，偶尔想喝甜的东西缓解一下`
- `memory_type=observation`
- `status=active`
- `confidence=0.7`

用户体感：

- 存储层虽然没有直接写成“喜欢甜咖啡”，但它还是把“这两天开会太多、想喝点甜的”沉淀成了长期 observation。
- 也就是说，问题不只是“有没有误写 preference”，还包括“是不是被 observation 换个方式长期化了”。

#### 5. 自然纠错后仍然没有把完整事项更新干净

第四轮纠错后，active 面里同时出现：

- 原任务：`你先帮我记一下，下班前我要给陈姐回个消息，至少把态度说明白，别一直晾着`
- 新碎片：`不是周五下班前`

后续问 `周五晚上我要干嘛来着？` 时，系统确实能回答出“给陈姐回消息”，但底层 active 记忆仍然是不干净的。

用户体感风险：

- 回答看起来可能还行，但底层库存已经脏了。
- 这类“表面回答还能凑合，后台记忆已经坏掉”的情况，后面会继续积累技术债。

### Persona 12 当前已确认的实际落库

- `profile|observation|说'这事我们回头再对一下'时，很多时候只是客气接住，不代表真想接|active|0.9`
- `event|event|你先帮我记一下，下班前我要给陈姐回个消息，至少把态度说明白，别一直晾着|active|0.95`
- `profile|observation|用户最近开会频繁感到疲惫，偶尔想喝甜的东西缓解一下|active|0.7`
- `event|event|不是周五下班前|active|0.85`

## 收敛后，最值得优先写进后续优化规划的问题地图

- `自然纠错只剩时间碎片或残句，完整事项不 supersede`

### Persona 3：健忘碎碎念型

#### 对话片段

1. `我先随便念叨两句哈，这两天脑子有点乱，总觉得有个事没弄完。`
2. `啊对，明天下午三点我要去找小林聊一下那个老是串味的回复问题，你先帮我记着。`
3. `还有我这两天老想喝柠檬茶，但这个你先别当真，我就是这两天嘴巴淡。`

#### 新发现

### 1. 纯碎碎念没有被误写，说明这条边界还不错

第一句只是情绪化、口语化的碎碎念：

- 没有写长期记忆
- `memory_processing.status=not_needed`

这说明系统对“随口抱怨/碎碎念”并不是一律过度写入，这条边界值得保留。

### 2. 但“你先帮我记着”被原样写进了记忆正文

第二句实际落库成了：

- `啊对，我要去找小林聊一下那个老是串味的回复问题，你先帮我记着`

而不是更干净的任务表达，比如：

- `明天下午三点去找小林聊回复串味问题`

用户体感：

- 系统把口语里的命令尾巴也当成事实写进去了。
- 这会让后续 recall 更像在复述原话噪声，而不是整理后的记忆。

### 3. 口语化“先别当真”这次守住了，但方式是低置信拒绝，不是稳定临时上下文策略

第三句没有误写长期偏好，这是好事；但 debug 显示它走的是：

- `memory_processing.status=rejected`
- `stage_reason=candidate_confidence_below_threshold`

也就是说，这次没写进去，主要是因为抽取出来的候选置信度只有 `0.3`，低于门槛，而不是明确命中了更稳定的“临时偏好只进 transient context”策略。

用户体感风险：

- 这轮没写错，不代表换个相近说法也能守住。
- 它更像“侥幸没写进去”，不是“系统真的理解了这只是临时感受”。

### 4. 更口语化的人设下，首轮闲聊也会很慢

第一句只是：

- `我先随便念叨两句哈，这两天脑子有点乱，总觉得有个事没弄完。`

但 `timing.total_seconds=24.59`，其中：

- `structured_router=11.78s`

用户体感：

- 连一句很普通的口语开场都要等很久。
- 越像真实用户，越容易暴露这种“明明没干什么却很慢”的问题。

### 当前续测结论

更口语化之后，问题有两个明显方向：

1. 口语噪声更容易混进记忆正文
例如：

- `你先帮我记着`
- `啊对`
- 类似命令尾巴或口语补丁

2. 临时偏好的守住方式还不够稳定
有时能命中 `source_transient_context_only`，
有时只是因为候选置信度太低被挡掉。

这意味着下一批 target 不只要测“会不会误写”，还要测：

- 写进去时正文有没有带入口语噪声
- 没写进去时，是命中临时上下文策略，还是只是低置信度偶然拒绝

### Persona 5：长辈口吻型

#### 对话片段

1. `我跟你唠两句啊，最近记性不太好，老怕自己把事情给忘了。`
2. `你给我记一下，后天下午我得去社区医院量个血压，回来顺路去拿一下眼镜。`
3. `不过喝豆浆这个事你先别往心里去，我这两天只是突然想喝热的，不是以后都这样。`
4. `哎呀我刚说岔了，不是后天下午，是大后天上午。`
5. `那你说说，我这几天主要惦记着啥？`

#### 新发现

### 1. “最近记性不太好” 会被直接写成长期 observation

第一句落库成了：

- `用户觉得自己最近记性不太好，担心忘事`

用户体感风险：

- 这很像当下情绪或临时状态，不一定是希望长期保存的稳定画像。
- 如果后面系统据此长期把用户当成“记性不好的人”，会有明显的贴标签感。

### 2. 长辈口吻下，口语指令前缀同样被写进正文

第二句落库成了：

- `你给我记一下，我得去社区医院量个血压，回来顺路去拿一下眼镜`

和前面的口语化 persona 一样，系统没有把“你给我记一下”这种入口指令剥掉。

这说明问题不是某一句特例，而是：

- `你先帮我记着`
- `真要记的是`
- `你给我记一下`

这类口语化“记忆命令前缀”都会混进长期记忆正文。

### 3. 回顾问题会继续吃带噪声的结构化记忆

后面问：

- `那你说说，我这几天主要惦记着啥？`

系统主要依据的还是结构化记忆，而结构化记忆正文里依然带着：

- `你给我记一下`

用户体感：

- 召回时不像在看整理后的记忆，更像在回放没清洗干净的原话。

### 4. 长辈口吻首轮也不轻，仍然偏慢

第一句 `timing.total_seconds=17.29`，主要还是：

- `structured_router=5.17s`
- `answer_directive=3.60s`

说明即便是更简单、更生活化的长辈式口语，首轮慢回复问题也依旧存在。

### 这组带来的额外结论

除了“临时偏好”和“任务纠错”，现在又多出一类值得补 target 的风险：

- **临时自我状态 / 自我担忧是否被过早长期化**

例如：

- `最近记性不太好`
- `这阵子脑子有点乱`
- `最近老怕忘事`

这类表达未必应该默认沉淀成长期 observation。

### Persona 6：学生拖延型

#### 对话片段

1. `我先跟你碎碎念一下，我这周其实有点摆，老觉得作业一大堆，但又没真开始。`
2. `不过你先帮我记一下，周四晚上我得把那份报告至少开个头，不然真来不及了。`
3. `奶茶这个你先别当我真喜欢啊，我只是这两天熬夜想喝甜的。`
4. `哎不是周四晚上，我说错了，应该是周五下午。`
5. `那我这几天到底在拖啥？`
6. `我最近爱喝啥？`
7. `周五下午我要干嘛来着？`

#### 新发现

### 1. “这周有点摆、没真开始” 被直接长期 observation 化

第一句落库成了：

- `我先跟你碎碎念一下，我其实有点摆，老觉得作业一大堆，但又没真开始。`

问题不只是写进去了，而是：

- 它几乎原样保留了碎碎念口气
- 它把一段很临时、很情绪化的拖延状态直接长期化了

用户体感风险：

- 用户只是说这周摆烂、没开始，不一定想把这种状态长期留档
- 后续系统可能会拿它当作“稳定的最近状态”持续召回

### 2. 任务正文继续混入口语前缀

第二句落库成了：

- `不过你先帮我记一下，我得把那份报告至少开个头，不然真来不及了`

这再次证明口语前缀污染不是偶发：

- `你先帮我记一下`
- `你给我记一下`
- `真要记的是`

这类话头现在都会混进结构化记忆正文。

### 3. “先别当我真喜欢” 这次没有守住，反而被写成长期 preference

第三句之后，库里出现了：

- `用户不喜欢奶茶，只是熬夜时想喝甜的`
- `memory_type=preference`

这说明和前面某些“临时偏好守住了”的 case 相比，这类更口语的说法：

- `先别当我真喜欢`

目前仍会误写进长期画像。

用户体感：

- 我只是说最近熬夜嘴馋，不代表长期偏好
- 但系统会把它转成“你不喜欢奶茶，只是想喝甜的”这种看起来很肯定的画像事实

### 4. 自然纠错仍会留下碎片 task

纠错后，库里没有干净地把原任务更新掉，而是出现了：

- `应该是周五下午`
- `memory_type=task`

同时还有一条：

- `用户更正之前提到的时间：不是周四晚上，是周五下午`
- `status=superseded`

这说明纠错链路比之前多了一点 lifecycle 动作，但最终 active 面上仍留下了一个没有业务语义、只有时间片段的 task。

用户体感：

- 纠错后不是变干净，而是变成另一种脏数据
- 后续问“周五下午我要干嘛”时，很可能继续被这种碎片记忆误导

### 这组带来的额外结论

学生拖延型把两类风险放大得很明显：

1. **临时情绪 / 自责 / 拖延状态是否被长期 observation 化**
2. **临时口语偏好是否被过早翻译成确定性 profile fact**

这两类都应该进入下一批 target。

### Persona 7：含糊社交型

#### 对话片段

1. `我就随口说说啊，最近老有人约我吃饭，我嘴上都说改天，其实心里根本没定。`
2. `不过你还是先替我记一下，这周末之前我得回一下小周，不然一直晾着也不太好。`
3. `咖啡那个你可别给我记死了，我就是这两天见人多，想喝点提神的。`
4. `不对，不是这周末之前，是周日晚上。`
5. `那你说我最近主要挂着什么事？`
6. `我现在到底爱喝啥？`
7. `周日晚上我要干嘛来着？`

#### 新发现

### 1. “嘴上说改天、心里没定” 被直接长期 observation 化

第一句落库成了：

- `最近有人约吃饭，嘴上说改天但心里没打算去`

这类表达其实更像：

- 模糊社交态度
- 当下的心理边界
- 一种随口吐槽

但系统把它保存成了长期 observation。

用户体感风险：

- 这种带一点社交策略和情绪色彩的话，用户未必希望长期被记住。
- 后续如果系统据此回答“你最近都不想跟人吃饭”，会显得非常越界。

### 2. 模糊任务的原句和纠错后的抽象时间 task 会并存

第二句先落成：

- `不过你还是先替我记一下，这周末之前我得回一下小周，不然一直晾着也不太好`

之后纠错句：

- `不对，不是这周末之前，是周日晚上。`

又新增了一条 active task：

- `截止时间是周日晚上`

问题在于：

- 原始任务正文没有清洗掉口语前缀
- 纠错后又只保留了时间，不保留“回一下小周”这件事

这意味着最终 active 面同时保留了：

- 一条带口语噪声的原任务
- 一条只有时间、没有业务语义的抽象 task

### 3. 模糊表述仍会被当成高置信度结构化事实

无论是：

- `嘴上说改天`
- `心里根本没定`
- `一直晾着也不太好`

这些都带有很强的口语、犹豫和社交语境，但实际落库时置信度并不低：

- observation `confidence=0.7`
- 原任务 `confidence=0.95`
- 纠错后时间 task `confidence=0.9`

这说明当前系统对“模糊、含糊、社交性表达”的保守性还不够。

### 这组带来的额外结论

现在又多出一类明确应该补 target 的风险：

- **模糊社交状态 / 礼貌话术 / 含糊承诺是否被过度长期化或过度结构化**

例如：

- `嘴上说改天`
- `回头再说`
- `先晾一会儿`
- `其实我也没想好`

这类话不该轻易被当成稳定 observation 或高确定性 task。

### Persona 8：情侣/家人碎念型

#### 对话片段

1. `我跟你唠唠啊，最近我妈老催我早点睡，我嘴上嫌她烦，其实也知道她是为我好。`
2. `你先替我记一下，周六中午我要回家吃饭，不然她又得念我。`
3. `还有豆花这个你先别给我记成真喜欢，我就是这两天突然嘴馋。`
4. `哎不对，不是周六中午，是周六晚上。`
5. `那我最近主要惦记着啥？`
6. `我最近爱吃啥？`
7. `周六晚上我要干嘛来着？`

#### 新发现

### 1. 家人碎念会被翻译成高度确定的长期 fact

第一句直接落成：

- `妈妈关心我的睡眠，常催我早睡，我心里知道她是为我好`
- `memory_type=fact`

这不是 observation，也不是临时状态，而是被提升成了很确定的长期事实。

用户体感风险：

- 这种话很多时候只是家庭碎念和情绪表达
- 系统却把它整理成了看起来很正式的长期家庭画像

### 2. 任务正文继续带口语命令前缀

第二句落成：

- `你先替我记一下，我要回家吃饭，不然她又得念我`

这里仍然没有清理掉：

- `你先替我记一下`

说明口语前缀污染正文的问题在家人语境里也完全存在。

### 3. 临时食欲被压成脱离上下文的 observation

第三句原本是：

- `豆花这个你先别给我记成真喜欢，我就是这两天突然嘴馋。`

结果库里留下的是：

- `就是突然嘴馋`
- `memory_type=observation`

问题在于：

- 原句里明确有“这两天”“先别记成真喜欢”
- 最终却被裁成了一条没有对象、没有场景、只有状态的 observation

用户体感：

- 这条记忆后面被召回时，甚至不一定知道是在说豆花
- 也会让“临时嘴馋”这种很短期的状态被长期化

### 4. 纠错后又只剩抽象时间结论

第四句纠错后，新增 active 记忆成了：

- `周六的活动/计划是晚上`

这和前面几组很像：

- 没有把原任务干净更新
- 只保留了时间变化
- 把“回家吃饭”这件具体事削没了

### 这组带来的额外结论

现在又确认了一类很值得补 target 的风险：

- **家庭/亲密关系中的碎念、抱怨、体谅混合表达，会不会被系统过度升格为长期 fact**

例如：

- `嘴上嫌烦，其实知道她是为我好`
- `老念我，但也是关心我`
- `嘴上说不要，其实也没真生气`

这类表达很多时候更像瞬时关系语境，不该轻易变成高确定性的长期事实。

### Persona 9：嘴硬心软型

#### 对话片段

1. `你别多想啊，我嘴上老说懒得见他，其实他真不来我又会觉得空落落的。`
2. `不过这个你先替我记一下，周五晚上我要去见他，别到时候我自己嘴硬又拖过去了。`
3. `可乐那个你别给我记成真爱喝，我就是这两天有点烦，想喝点冰的。`
4. `等下，我说错了，不是周五晚上，是周六晚上。`
5. `那我最近到底在别扭什么？`
6. `我最近爱喝什么？`
7. `周六晚上我要干嘛来着？`

#### 新发现

### 1. 第一轮反话被隐私门控挡住了，但后续同类信息仍会换路径落库

首轮里，系统其实抽出了这条候选：

- `虽然嘴上说懒得见某人，但对方不来时会感到失落`

但因为被判断成更私密的关系情绪，最终走了：

- `candidate_privacy_requires_confirmation`

这一步本身是好事，说明“嘴硬心软”的深层情绪没有直接被长期写入。

但问题是，后面相关信息还是会以别的方式回流进库。

### 2. 临时可乐偏好又被翻译成确定性的长期 preference

第三句之后，库里出现：

- `用户并非真爱喝可乐，只是心情烦想喝冰的`
- `memory_type=preference`
- `confidence=1.0`

这说明虽然系统没有把“嘴硬心软”关系情绪直接写进去，但对“烦了想喝点冰的”这种临时状态，仍然会过度确定化。

用户体感：

- 我只是这两天烦、想喝冰的
- 系统却给我整理成一条看起来很稳定、很肯定的偏好画像

### 3. 反话和临时状态被 observation 进一步糅成一条脏总结

后续 observation 里出现了：

- `用户将一个计划改期至，并有自我提醒去见某人、避免拖延的需求，同时用户喝可乐主要是为了缓解烦躁情绪而非真喜欢可乐`

这里至少有两个问题：

- `改期至` 这段是残句，语义不完整
- 去见某人和喝可乐的临时情绪被硬揉成了一条 observation

这说明不仅单条记忆会脏，后台 observation 反射层也会继续放大这些脏输入。

### 4. 纠错后仍然会留下时间碎片 task

纠错后 active 面同时存在：

- `计划改为周六晚上`
- `周六晚上`

而更具体的“去见他”这件事没有被干净更新，只剩抽象时间。

这和前面多组结果保持一致：

- 纠错之后，系统倾向保留“时间变化”
- 但丢掉原本真正该做的那件事

### 这组带来的额外结论

嘴硬心软型让另一个问题更明确了：

- **系统虽然有时能挡住深层私密情绪，但仍会把相邻的临时态度、烦躁状态、口语计划翻译成高确定性长期画像**

也就是说，当前不是简单的“全挡住”或“全放过”，而是：

- 深隐私情绪可能被 gate 拦住
- 但相邻的口语化临时状态仍会换一种更温和、却仍然过度确定的形式写入
